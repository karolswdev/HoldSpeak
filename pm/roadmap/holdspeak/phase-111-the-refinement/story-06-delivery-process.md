## The thesis (the bar)

The delivery belt, the process window, and the project memory window
are the kernel-facing programs — the operator watching the machine
work. The bar: **they read as instrumentation: belts and process
tables in dense mono rows, states carried by bevel and etch, not by
colored pills and progress toasts.** Workbench 2.0 grammar, dark
2004-techy render.

## Method (phase canon)

1. **Audit.** An agent walks the belt, process window, and project
   memory window as rendered today; files every SaaS-ism.
2. **Rethink.** Propose the native interior against the phase
   question — layout, density, controls, typography.
3. **Implement** in `web/src`.
4. **Prove** with live screenshots on the real desk, 1440 and 393.

## Test plan

- The belt renders as a dense instrument strip, not a toast stack.
- Process rows are a mono table with full-width hover bands; state is
  etched/beveled, not pill-colored.
- Project memory reads as a filed archive consistent with the rest.
- Screenshot walk at both viewports, no overflow.
