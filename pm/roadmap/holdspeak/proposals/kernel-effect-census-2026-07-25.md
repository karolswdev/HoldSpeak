# HoldSpeak consequential effect-callsite census

Snapshot: `holdspeak/` source at `ecc8308021a48c3fa66baafe79b16196c11bffbb`,
inspected 2026-07-25. Scope is `holdspeak/`, including ignored source paths under it.
Generated bytecode, source maps, and vendored/generated static assets are not source
callsites and were excluded.

## Result

There are **40 static, effect-capable source statements** in the requested families:

- 4 invocations of the tmux text/key transport boundary;
- 8 direct `TextTyper.type_text` invocations;
- 5 subprocess dispatch/boundary sites in plugin or connector code;
- 13 outbound network/model-egress sites in intel, actuator, or connector code; and
- 10 raw clipboard, keyboard/Accessibility, or AppleScript typing primitives.

Only **4/40 are universally covered** by one of the RFC's existing audited
chokepoints. The other **36/40 bypass, are mixed, or expose a dormant unowned raw
path**.

This is a static callsite count, not a count of logical user actions. A single
logical action can cross several listed statements (for example,
`gated_connector._route` → `PermissionGate` → `urlopen`). Those statements remain
separate census sites because the RFC's confinement work must pin every ambient
effect boundary.

## Counting and classification rules

The census uses the RFC's consequence rule in §10 and the effect-capability boundary
in §5b:

- For tmux, the counted API boundary is every invocation that can resolve to
  `tmux_transport.send_text_to_pane` or `send_keys_to_pane`.
- For `TextTyper`, both direct `type_text` invocations and the raw OS/clipboard
  primitives behind it are counted. Constructor/import-only references are not
  effects.
- For connectors/plugins, both a direct gate call and the shared raw dispatcher
  behind it are counted when each is an effect-capable statement.
- For network/model egress, the socket/HTTP/client invocation is counted. Building a
  request or a `GatedOperation` plan is not itself egress.
- A retry or compatibility fallback at a different source line is a separate static
  callsite even when only one branch executes per attempt.
- “Covered” means **every in-tree route** into that statement passes
  `coder_steering.deliver`/`deliver_keys`, the actuator executor, or delivery
  commands, with no unowned dormant raw branch.
- “Mixed → bypass” means a shared statement has at least one covered route and at
  least one route that avoids all three chokepoints. Mixed sites are counted in the
  bypass column.
- “Dormant bypass” means the effect-capable statement has no current production
  caller but can execute without a named chokepoint. It is counted as bypass because
  it remains an ambient capability.
- `connector_runtime.PermissionGate`, connector run records, dictation journals,
  `RunLifecycle`, and route-local permission checks are useful controls, but none is
  one of the three audited chokepoints named by the task. This agrees with RFC
  §5b's statement that `PermissionGate` is honest enforcement, not a security
  boundary.

Operation names after an `external.` prefix below are recommended concrete registry
types. Where one shared statement multiplexes several effects, all required types are
shown.
