# HS-109-08 - Closeout — the sitting on real memory

- **Project:** holdspeak
- **Phase:** 109
- **Status:** done
- **Depends on:** HS-109-07
- **Unblocks:** phase close
- **Owner:** unassigned

## The thesis (the bar)

Article IX.4: the owner's live verdict outranks every green suite.
The phase claims the Desk remembers — so the sitting is the owner
using HIS archive's memory, not a seeded diorama (the standing
verify-on-the-real-thing rule).

The bar: **the machine beats are one rerunnable command against real
archive data, and the sitting is the owner driving them plus the
felt walk** — with any held questions carried to him named, never
absorbed.

## Problem

Seven stories can be green and the memory can still feel like a
database. Only the owner can cast that verdict.

## Recipe

1. **The beats script.** `scripts/phase109_closeout_beats.py`, one
   command, each beat printing PASS/FAIL by name:
   - B1: backfill idempotency on the real archive (counts, second
     run no-op).
   - B2: a decision record with a verified transcript moment; the
     jump resolves.
   - B3: promotion — deterministic ADR with `decision:<id>` lineage;
     supersession propagates; superseded re-promotion refuses by
     name.
   - B4: model-assisted promotion through `inference.run@1` against
     `.43`; receipt read back with destination.
   - B5: memory search over the real archive — ranked cross-kind
     hits; the wire-defect regression test green.
   - B6: grounded ask-this-project on `.43` with citations and the
     grounded-on count; control-vs-treatment delta shown.
   - B7: the process window folds a live run's real events; cursor
     replay after hub restart byte-equal; pending-forever stays
     Waiting.
   - B8: the sweep — full suite, web chain, guards, spine
     byte-unchanged (`git diff --exit-code` over
     broker/admission/journal/model/executor), register untouched
     (21/3/3/15 exactly as Phase 107 left it).
2. **The sitting sheet.** `OWNER-SITTING.md`: the eight beats in
   owner terms plus the felt walk — open a project he actually
   works, read its timeline, find a real decision by text, follow it
   to its moment, supersede something true, promote something real,
   watch the process window while dictating. Any held questions
   listed with the options.
3. **Verdict recorded verbatim**; walk-blocking defects fixed and
   re-walked, or the phase does not close.
4. **At close:** final-summary.md, README pointer + phase table,
   BACKLOG updated (anything this phase spawned filed as candidates),
   memory of record updated.

## Out of scope

- New features. A defect found at the sitting is fixed as a rider
  only if the owner charters it (the Phase-104 precedent).
- Phase 108 scoping — already reserved.

## Acceptance

- All eight beats pass in one session, rerunnable, on real archive
  data and real `.43` metal.
- The owner drives the beats and the felt walk; verdict verbatim in
  evidence.
- Exit criteria in `current-phase-status.md` all checked or
  explicitly retargeted with reasons.
- Final summary written; pointers moved; the register provably
  untouched by the whole phase.

## Test plan

- **Machine:** the beats script (staged repeatedly before the owner
  sits).
- **Owner:** the sitting (Article IX.4).
- **Evidence:** beats output, sitting record, verdict, suite counts.

## Chef's notes

- Stage the beats until they pass twice consecutively before asking
  for the owner's time — his sitting is the scarcest resource in the
  process.
- The felt walk should start from HIS most-touched project; ask him
  to name it at the top of the sitting rather than guessing.
- Latency honesty: memory queries are reads and owe no admission —
  but print their times anyway; a slow memory is a memory the owner
  stops asking.
