# The Conductor

Owner direction, 2026-10-05: "I wanted it to work with agents. In a semi-autonomous way. As an orchestrator. And out of the box. And batteries included." Then: "Make it happen."

## The loop

1. **Ready.** First run finds `claude`, `codex` and `tmux`, and installs the agent hooks with one press. `holdspeak doctor` checks the same.
2. **Hand to agent.** One verb on an action item, a decision, a Room issue, a Note, or a dictated sentence (Thread `/agent`, MCP `agent.hand`).
3. **Brief.** HoldSpeak writes a grounded brief: the item, its meeting quote, the Project's decisions and open commitments, memory pages, `.hs/` facts, the Control mode, acceptance. People data is cut before it reaches a cloud agent.
4. **Launch.** Claude Code or Codex starts in its own git worktree, with the brief as its first message, under HoldSpeak's spawn settings (rider hooks and the tool gate).
5. **Supervise.** The tool gate decides by Control mode. A waiting agent joins **Needs you** at once. A routine question can get a drafted answer under policy. A real one reaches you, and you answer by voice.
6. **Follow through.** The Heartbeat follows the PR. On merge, the originating commitment closes with the PR as evidence, the weekly update reports it, and the session and the clean worktree are cleaned up.

### The Control-mode mapping (owner rules)

Ratified by the owner, 2026-10-06. YOLO is the default posture.

| Mode | Launch | Agent tool calls (Bash) | Agent question |
| --- | --- | --- | --- |
| **Secure** | You press to launch | Every call waits for you | Always to Needs you |
| **Normal** | Launch on the verb | Read, test, `git status/diff/log` pass; the rest waits | Drafted answer shown; you send |
| **YOLO** (current default posture) | Launch on the verb | Pass in the agent's own worktree | Routine ones answered under policy and receipted; real ones to Needs you |

### K5 as built

- **The tool gate.** The hook reads each held Bash call in the agent process (`holdspeak/tool_gate_rules.py`) and sends the hub a verdict, never the command: `inside`, `outside` or `unparsed`, the rule, and the Normal read/test rule. The hub checks the verdict against the caller's own launch (its registered session, its worktree, its branch) and `resolve_policy` (family `tool_gate`) applies the mode. Secure holds every call. Normal passes `git status|diff|log|show`, the read forms of `git branch`, `ls`, `cat`, `rg`, `grep`, `find` (no actions), `pytest`, `uv run pytest`, `npm test`, `npx vitest run` and a few more, in the worktree. YOLO passes every call whose working folder and named paths are in the worktree, and `git push origin <the launch branch>`. A call that names a path outside (also through a symlink), a URL, `cd ..`, `bash -c`, `eval`, inline code, a variable or a command substitution waits. A call from a session that is not the launch keeps the owner's recorded hold; before the rider registers the session, no call is the launch's. The verdict names its proposal id and args hash, and a verdict copied to another call waits; a proposal id is one session's. A here-document ends at its first tag line, as in bash; `find -exec` waits; each command word is identified first: a bash builtin, a system program (a bare name the PATH resolves outside the worktree, relative PATH entries read from the call's folder), or other. Only a builtin or a system program earns read authority or the `cd`, `git` and here-document `cat` readings; a path-invoked or PATH-shadowed program never moves the assumed folder. `PATH=...` prefixes and builtins that change resolution (`export`, `source`, `enable`, `alias`, ...) wait. One exception (R5): `source <path>` or `. <path>` alone, read on the original command, where the path is plain text with a slash (no quote, `$`, backquote, backslash, glob or `~`) and resolves (symlinks followed) inside the worktree to `bin/activate` of a venv (`pyvenv.cfg` two levels up), is `inside` with no read rule, so YOLO passes it and Normal and Secure hold it; chained, piped, redirected or with an argument, it waits. YOLO runs programs inside the worktree (`./build.sh`, `pytest` with its conftest, `npm test`): that is the ratified posture, and such a program can still write outside. Each automatic decision is approved by the `control-mode` principal: the gate audit row and the kernel journal name the mode and the rule.
- **Answers.** A waiting launched agent (a K3 wait) is triaged by mode (`holdspeak/services/agent_responder.py`). Secure: Needs you, no draft. Normal: Needs you at once; a draft is stored on the wait. YOLO: the wait is held back while the model assigned to Cadence drafts writes a draft and a class from the brief, the pane tail and the Project's memory. The word list reads the draft answer too. Before the model runs, Secure and a permission prompt go to the owner at once (no draft), and a wait a YOLO triage held back is shown at once if the mode is now Normal. Each record is written only while its wait is the stored one, so an older worker never replaces a newer wait. Before anything is typed, the wait, its question, its kind and the mode are read again: a wait the owner answered is left alone, a changed one goes to Needs you. ROUTINE is typed into the agent's own pane through `process.input` (the pane is checked again) and receipted on the session (`auto_answered`); no Needs you row and no notification. REAL goes to Needs you with the draft and notifies then. No model, a model error, a word from the REAL list, 6 answers in the last hour, or the same question again: REAL. A permission prompt is never answered here.
- **Limits.** At most 3 launched agents run at one time (`agent.hand` refuses `launch_cap_reached`). A running agent with no hook activity for 2 h, or running for 8 h, gets one Door item each (Needs you); nothing is stopped.
- **Fixed on the way.** The hook of a gated launch named the launch's `process.spawn` operation as its kernel parent, and the kernel refused that parent for the agent (`parent_operation_scope_required`): every Bash call of a launched Claude was denied. The hub now keeps the link as the verdict's `launch_id` and does not send the spawn as the parent.
- **Codex gap (closed by R3).** See "R3 as built".

A deny is `hookSpecificOutput.permissionDecision: "deny"` with a non-empty reason (Codex shows "Command blocked by PreToolUse hook: <reason>" and does not run the call). Codex refuses `permissionDecision: "allow"` and `"ask"` ("unsupported"); an allow is no output. A hook held 20 s under a 300 s timeout ran the call after it. Codex has no `Notification`: its approval prompt fires `PermissionRequest` (`tool_input: {command, description}`), and the end of a turn fires `Stop` with `last_assistant_message`. An untrusted or changed hook does not run (`codex exec` says nothing; the TUI opens "Hooks need review"). `agent_hooks.install` for Codex writes the rider `hooks.json` and then trusts HoldSpeak's hooks only (the installed rider and the launch hooks), through `codex app-server` (`hooks/list`, then `config/batchWrite`, Codex's own writer). A Codex launch whose hooks Codex does not trust refuses before anything runs (`codex_hooks_untrusted`). `process.spawn` and Hand to agent launch Codex gated (the gate armed for the new worktree).
- **The gate.** `holdspeak gate hook --agent codex` names its sessions `codex:<session_id>`. Inside a launch the hook authenticates with the launch credential of its tmux session (`agent:launch:<id>`, K6); the hub now takes that credential as the call's own launch. Before R3 this check compared only `claude:<session>` keys, so it never found the launch of a real launched agent.

The folder-trust screen ("Folder access" / "Trust this folder? ..." / "› 1. Trust and continue" / "2. Quit" / "enter continue · esc quit"; under the daemon: "2. Back to Agent Command Center" / "esc back") is answered for exactly the launch's worktree: Enter at most once, Up at most once, each a receipted `process.input`. "Hooks need review" is never answered (`trust_state: hooks_review`).
- **The submit.** Codex reads text typed at once as a paste and drops a carriage return sent right after it. The tmux transport now waits 0.3 s before the submit (0.1 s was enough in the test).
- **Waits.** A `PermissionRequest` is a wait TO APPROVE (never answered by the responder); a `Stop` is a wait TO ANSWER with the last message as its question (Claude Code's idle prompt).
- **Approvals by Control mode** (ruling 2026-10-06). YOLO: `--ask-for-approval never --sandbox workspace-write -c sandbox_workspace_write.network_access=true` (the sandbox has no network by default; the agent must `git push origin <launch branch>` and `gh pr create`, and the gate still holds URLs and other pushes), plus `--add-dir` for the worktree's own git folder (`.git/worktrees/<name>`) and the repository's `objects`, `refs` and `logs`. Operation not permitted` with the parent, a commit on the launch branch with the exact folders). Secure and Normal: `--ask-for-approval on-request`; Codex's prompts go to Needs you as TO APPROVE. A real YOLO run committed on its launch branch with no prompt, and the gate held `cat /etc/hosts`.
- **Receipts.** Codex sessions have their own adapter, `codex-hooks` (tool hooks and blocking authoritative, usage unavailable).
- **Push and pull request.** A real YOLO run pushed its launch branch to a local bare remote over `git://127.0.0.1` and ran a fake `gh pr create` that reached a local endpoint; both passed the gate (`git_push_launch_branch`, `in_worktree`). Without the network flag, `git ls-remote origin` in the sandbox got nothing.
- **Fast hooks.** Rider hooks timed out under load at 5 s ("hook timed out after 5s"; the event is lost): `holdspeak agent-hook ingest` loaded all of `holdspeak.main` (2.2–3.6 s cold). The console entry is now `holdspeak.cli_entry:main`: `agent-hook ingest` and `gate hook` load only their own modules (0.1 s; 0.5 s through `uv run --project`), every other command goes to `holdspeak.main`. Wrapped folder rows join with nothing between them; a space the wrap may hide is never guessed.

### R2 as built (durability)

- **Restart.** The hub writes every agent credential to `agent_credentials` (the SHA-256 of the token only, never the token) and each launch's origin item and created records to `agent_launch_ownership`. At start the hub loads the live rows. A running agent keeps its MCP access, its palette, its memory read, its grants and its ownership through a hub restart.
- **Writes.** An issue and its first scope are one transaction, written before the credential is live. A write that fails is not acknowledged: an issue or an ownership record fails, and a revoke answers false. A revoke that is not written is refused in memory at once and written again before every later credential write (issue, ownership, target) and on a repeated revoke; the Settings revoke answers 503 `credential_revoke_not_persisted` and the same DELETE retries it. No replacement credential is issued for that identity until its previous revoke is written. If the hub stops before that write, the credential comes back at the next start.
- **Life.** The remaining life of a row is read from clocks sampled after the rows are read. On the same machine boot, the monotonic deadline is also checked and the smaller one wins, so a slow start or a wall clock set back never extends a credential. A row with no life left is marked `expired` and is not loaded.
- **Grants.** At start, after the composition, the hub installs the revoke hook and then ends every LIVE launch grant (desk or project) whose launch has no live credential: the credential expired while the hub was down, or the hub stopped between the two revokes.
- **Targets.** A tmux target taken from another credential leaves that credential's stored targets in the same transaction.
- **No token on argv.** The spawn writes the token to a 0600 file in `~/.holdspeak/agent-env/` (0700). tmux runs `/bin/sh -c BOOTSTRAP holdspeak-agent <file> <command>` directly: no user shell and no rc file runs before the token is read. The bootstrap turns tracing off, reads the file with `read`, deletes it, and then runs the user's shell with the command. The spawn waits up to 15 s for the file to go, then 0.3 s more, and needs a live pane in the session; if either fails, the spawn fails, the credential is revoked and the file is removed. A failed file write revokes the credential before tmux runs. A new window in the same tmux session does not get the token.
- **A held call through a restart.** The restart still invalidates every held proposal (HS-104-02: never resume a pre-restart hold). The hook waits for a hub that stopped answering for up to 20 s in a row, then proposes the same call again as `<id>~r1` (at most 3 times) with its surviving credential; the new hold is decided by the Control mode or the owner. A hub that stays down: the call is denied, as before.
- **Session credentials.** A credential the hub mints for one Claude session (`claude:<session id>`) ends on every SessionEnd, `/clear` and `/resume` included: the next session mints its own. The launch's process credential stays over `/clear` and `/resume`, as before.

### R4 as built: hand and close more kinds

- **Hand a Room issue.** `agent.hand` takes `issue`. The id is `<watch_id>.<entity_id>` (`issue:w-ledger-jira.PAY-418`), the Room Watch and its entity (`holdspeak/services/agent_issue.py`). The Room's issue rows (a Jira `issues` Watch) carry `kind: issue` and `entity_id`, so the row verb shows on them (canvas K2e). The brief carries the title, the labels, the status, the URL and the Room's context. The body is read once, at brief time, with the Watch's own read-only CLI (`acli jira workitem view`, `gh issue view`). A failed read is named in the brief (`Body: not read`). The Jira read never runs `auth switch`: it reads `auth status` under the acli lock and reads the body only when the active account is the Watch's (else `Body: not read`). The read leaves the machine, so the launch sheet names it at the fetch: an EgressChip with the tracker host and READING, READ or NOT READ. The brief tells the agent not to write `Closes #N`: the owner closes the issue. GitHub issue rows come from a GitHub issues Watch (`gh issue list --state open`, read-only, no assignee or author read; allowlisted in `connector_packs/github_cli.py`). The Door arms it with the PR review queue (`watch.github.open_issues`), so a Room with a GitHub repository has issue rows out of the box. Its rows read `#418 Title` · `ISSUE · OPEN 2 D`; they stay in the Room's OPEN HERE and out of the desk Needs you count (a busy repository would flood it). A new issue is `github.issue.opened`, never a PR event.
- **Every origin has a close.** On merge: `action` completes; `decision` and `decision_record` link the PR (K4). `project_item` takes the done state of its type (milestone `reached`, risk `mitigated`, dependency `resolved`, workstream `done`); a signal is linked, it has no done state. `note`, `meeting`, `artifact` and `issue` get the PR linked in their Room: one `conductor.pr_linked` observation and one evidence link (`merged_pr`), both identified only by the Room, the origin and the PR URL (a retry after an interrupted save, with a renamed origin, is the same link). Nothing is written to GitHub or Jira. Secure asks first, with the same Door item.
- **The confirm item has an owner.** The Secure `Merged: confirm close` item and the K5 budget items are the owner's (`me`), due today. Needs you counts them as DUE TODAY, not UNASSIGNED.
- **A removed worktree leaves the registry.** When K4 removes a worktree (or finds it gone), the cleanup unregisters it from the Delivery registry, last, with an audit receipt (`worktree_unregistered`). The source's own checkout is never unregistered. A kept worktree stays.
- **Every merge in the weekly update.** On each sweep the Heartbeat reads each Room repository's merged PRs: one `gh pr list --state merged --limit 30 --search merged:>=<8 days ago>` per repository (the repositories of the Room's GitHub Watches and the repositories filed in the Room). Each repository has a completed-through watermark: each read is `merged:<watermark>..<now>`; a full read (30) halves the window and stores the narrowed end as a continuation; a full window of 60 s or less is paged by creation time (`sort:created-asc`, `created:>=<cursor>`, the cursor stored); the watermark moves only past a window whose last read returned fewer than 30 (at most 4 reads per repository per sweep). The first lower bound (8 days back) is stored before the first read and kept until it is drained; after that a hub that was off for weeks continues from its watermark. Each merge is one `conductor.pr_merged` observation per Room, keyed by the PR URL. The weekly update reports it (`Merged: <title> (PR #n)`). K4's own line for an agent PR has the same key, so a PR is reported once. Room Watches stay open-only. The setting `report_merged_prs` (Heartbeat settings, `PUT /api/settings/heartbeat`, MCP `heartbeat.set`) is ON by default; it is the owner's question whether to keep it.
- **Hand the same item again.** K4 keeps a merged branch. A later hand-off of the same item takes the next free round: `hs-<kind>-<id>-2` on `hs/<kind>-<id>-2` (R1's real walk refused `worktree_duplicate`).
- **No real `gh` or `acli` in tests.** `tests/conftest.py` sets `HOLDSPEAK_TEST_NO_REAL_CLI=1`. A production default runner (`PermissionGate.run_read_subprocess`, the PR receipts runner) then refuses `gh` and `acli` by name (`real_cli_refused_in_tests`, `holdspeak/cli_guard.py`), unless the program is a test's own stub under the temp folder.
