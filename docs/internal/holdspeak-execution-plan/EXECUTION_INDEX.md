## 1 The outcome and the order

Improve two complete jobs: **build and deliver technical work** and **direct people, decisions and follow-through**. Existing features should retain context, truthful state and authority as the owner moves between them. Refactoring supports those jobs, not a new folder scheme for its own sake.

Use the same sequence for each accepted slice:

```text
assigned environment + current instructions + source drift check
    → one explicit behavior decision for this slice
    → named producer/consumer characterization and baseline
    → narrow implementation with focused proof
    → independent review + integrated checks by the owning role
    → bounded completion report; hold for separately authorized shipping
```

Do not wait for all product questions before progressing one independent slice. Do not begin a platform rewrite to unblock a local correction. Preserve the existing hub, Desk, native/device and plugin boundaries unless a concrete accepted change requires otherwise.
