## Work

1. Extend handled error/result propagation with the accepted actual stage and identity metadata. Capture acknowledged canonical PR URL/number, prepared head/base/branch, target and phase when available. Keep credential-bearing origin strings out of storage. Retain old optional fields and all historical rows; no new table or general pre-effect claim. The narrowly specified owner-Merge request receipt below is the only new pre-command barrier.
2. Preserve phase facts through handled merge nonzero/exception paths. Catch ordinary injected process/transport failures at the delivery boundary into truthful failure/unknown receipts, retaining known identity. Do not catch process termination or pretend this prevents all unrecorded effects.
3. Derive allowed actions from evidence: strictly proven pre-remote failure may Retry; identified known PR may Check; legacy/incomplete or uncertain remote results remain explained and blocked from rebuilding. A later friendly error cannot wipe earlier known effect identity. Retain a merge-requested/uncertain marker after any unconfirmed merge attempt; later open/queued reads cannot silently reoffer Merge. Keep Skip terminal without changing Program Done or deleting/cancelling remote work.
4. Add the accepted delivery-local read using the existing injected runner seam. Check issues one bounded PR read and no DW/worktree/commit/push/create/merge. Validate canonical repository/number/URL, branch/base/head and fork/state expectations. No list-by-branch adoption, fallback to a source registry or unknown-state→closed coercion.
5. Own the safe `turn_item` recovery/status/checkpoint-ID projection consumed by task03. A current `delivery_ref` change must not relabel the old PR: use stored original target/phase for continuation and refuse preparation Retry on target drift. An open matching Check creates the accepted current continuation receipt. An already-merged matching Check records reconciliation, not a new merge. Unavailable/malformed/closed-unmerged/mismatched results retain identity and explain what is unverified. Preserve history and distinguish observation from effect.
6. Add optional expected-checkpoint forwarding through the existing route/service method; compare the displayed positive integer against the latest delivery row under the current decision lock before Check/Retry/Merge/Skip under the accepted first-branch contract. Recheck the current Program/receipt context inside that lock; do not silently rebind to changed repository or delivery target. Do not infer it from current state. Scope the requirement to the accepted delivery contract; unrelated decision kinds retain existing behavior.
7. For every accepted owner-initiated known-PR Merge, including fresh Secure, re-read the exact target, then successfully commit the owner-requested/unconfirmed `kind="delivery", choice="pr_open"` checkpoint before the remote command. If append fails, issue zero merge commands. Use the recorded head as a provider-side condition, issue at most one merge, then observe. The committed marker remains on every later observation/error row until merged; if an outcome append fails, the request row still prevents ordinary reoffer. If the process stops before the command, the row remains truthful requested/unconfirmed, not active/failed, and Check/Skip only. Mark Delivered only on matching confirmed merged state. Success-but-queued/open and unavailable post-read remain awaiting verification; no silent remerge, polling or auto/admin mode. Initial automatic merge policy remains separate unless G32 explicitly expands it. The head condition is not an atomic base/fork condition; keep that residual limit explicit.
8. Extend the fake deliberately for URL-targeted reads/merge, conditional-head checks, malformed/nonzero/raised outcomes and success-before-error. Unsupported gh calls fail closed, never execute the CLI. Record non-gh commands too; verify known-PR continuation never repeats DW, commit, push or create. Existing local Git rig is still real local execution, not a pure fake.
9. Add C32 unit/integration assertions, including stale/missing expected ID, changed head between Check and Merge, wrong repository with the same PR number, phase preservation and no extra steps/agent launches. Preserve initial Secure/Normal/YOLO policy tests, adding the accepted owner-Merge barrier at Secure. Test pre-command append failure, reconstruction after marker before command, post-command append failure and marker retention through read failures. Initial automatic and full preparation-Retry crash/receipt gaps remain explicit.
