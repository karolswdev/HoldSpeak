## What the window manager already has

The shared manager is real and concentrated in `DeskWindow.tsx`. Its module
contract says every window adopts `useDeskWindow` through `DeskWindowFrame`
(`web/src/desk/components/DeskWindow.tsx:1-12,155-157`). The hook presents a
window without blindly raising a rehydrated plane, clamps a saved rectangle,
and places an unsaved rectangle into the work band
(`web/src/desk/components/DeskWindow.tsx:192-259`). Its cleanup explicitly
forgets an unarranged rectangle and retires the panel order entry
(`web/src/desk/components/DeskWindow.tsx:285-293`).

The existing Workbench-grade primitives are concrete:

|---|---|---|

| Maximize / restore | `web/src/desk/components/DeskWindow.tsx:737-753,807-847`; `web/src/desk/store/compositorSlice.ts:331-341` | `panelMax` replaces the normal rect with the work band, while the saved rect remains available for restore. Head double-click and chrome verbs toggle it. |

This is a solid seam to extend. There is no named zoom API; “zoom” is the
maximized full-work-band state. There is no named virtual-screen or per-screen
arrangement in the manager source inspected. The workspace document has only
`panel.rects`, `panel.order`, `panel.max`, normalized windows, zone ids, and
zone view preferences (`web/src/desk/store/workspaceStorage.ts:15-33`). The
other view state is list/spatial (`web/src/desk/store/types.ts:37-38,222-227`),
not an Amiga-style screen/workspace model. The final `rg` in the source probe
is an absence check against these manager paths, not live proof.

The persistence document is strict and versioned, but it is not yet a single

## Shared window species and hand-rolled bodies

The frame shell is genuinely shared. There are 19 production
files with `<DeskWindowFrame>` calls under `web/src/desk` (source probe count,
tests excluded), including SurfaceWindows, Pullout, Info, Repo, Roadmap,
Workbench, Ask, Delivery, Trust, Zone, and Thought workspace hosts. The shell
owns the title/icon/action/wings slots, lifecycle, focus, chrome verbs, and
resize edges (`web/src/desk/components/DeskWindow.tsx:496-542,705-753,800-882`).
Its close/minimize/maximize controls are library `Button` species
(`web/src/desk/components/DeskWindow.tsx:823-850`), and the shell's right-click
menu is the shared `WorkMenu` (`web/src/desk/components/DeskWindow.tsx:861-875`).
The Button species itself centralizes the actual button element, disabled and
loading grammar, and chrome variant (`web/src/components/signal/Signal.tsx:21-74`).

The frame also has reusable system furniture: `windowGeometry`,
`windowRegistry`, Dock, Expose, Switcher, SnapGhost, and command adapters are
split under `web/src/desk/components/window/` and re-exported by
`DeskWindow.tsx:28-88`. Surface-hosted applications have an additional
convergence seam: `SurfaceWindows` provides a shared frame, Surface body,
ApplicationBoundary, title/wing slots, and portaled footer slot
(`web/src/desk/components/SurfaceWindows.tsx:151-210`). The surface barrel
exports SurfaceLedger/Rows, gadgets, chips, Disclosure, ProgressPlan,
SurfaceFooter, and MicButton (`web/src/desk/surface/index.ts:1-149`), while
SurfaceFooter portals egress/receipt/verbs into the frame foot
(`web/src/desk/surface/SurfaceFooter.tsx:6-32`).

The content species are still mostly host-owned. `DeskWindowFrame` exposes a
generic `children` slot (`web/src/desk/components/DeskWindow.tsx:539-564,877`),
so the 19 bodies can choose their own structure and CSS. The largest
production body/style hotspots, excluding tests and `_parked`, are:

## Ranked owner-cost findings

1. **J1/J2/J3/J4/J5 — return context is not one product promise.** Static
   registry surfaces persist their open instance, scope, geometry, order, and
   max state. Pullouts, Info, Roadmap, Repository, and Workbench windows do
   not persist their open instances because their arrays are absent from
   `DeskWorkspaceDocumentV1` (`web/src/desk/store/workspaceStorage.ts:15-33,120-153`;
   `web/src/desk/store/types.ts:153-176`). A Senior Architect can arrange a
   meeting/project/thought context and still return to a Desk that requires
   reconstructing those windows. This fails Tenets 3, 6, and 7 and
   Constitution Article VII.3 (the user's arrangement persists).

Body convergence is an inspection target. A generic children slot and file
size do not themselves establish a Tenet 5 violation. Direct raw controls and
rendered inconsistencies need their own evidence; the consolidated finding in
`../structure.md` names a direct example and treats scanner hits as candidates.

## Source boundaries with no finding yet

- **J1/J2/J3/J4 — named screens remain an ambition candidate.** The current
  manager has one global panel order, one max set, and one workspace document
  (`web/src/desk/store/types.ts:209-221`;
  `web/src/desk/store/workspaceStorage.ts:15-24`). Expose is a picker grid
  over that one set, not a screen switcher
  (`web/src/desk/components/window/Expose.tsx:23-25,55-149`). List/spatial is
  a view mode, not an arrangement identity (`web/src/desk/store/types.ts:37-38`).
  The plan explicitly lists screens and automatic arrangement as candidates,
  so this has no Tenet or Article failure assigned.

- **J1/J2 — first-value recovery has an intentional open-set boundary to
  verify.** The recovery-only SurfaceWindows effect clears `windowsById` and
  writes the empty set (`web/src/desk/components/SurfaceWindows.tsx:90-95`;
  `web/src/desk/store/compositorSlice.ts:265-268`). The source comments make
  this intentional for first use, and the same effect is reached through the
  `arrivalRequired` remount in DeskApp (`web/src/desk/DeskApp.tsx:297-300`).
  No producer trace here demonstrates that an ordinary return reaches
  `arrivalRequired`, so this is a boundary for the charter to verify, not a
  destructive owner-cost finding or canon failure.

- **No owner-cost finding established for stale panel ids.** Workspace
  loading validates id shape and compacts arrays, but does not cross-check
  `panel.order` or `panel.max` against registered windows
  (`web/src/desk/store/workspaceStorage.ts:35-49,89-114`). The front scan
  ignores ids absent from `windowRegistry`
  (`web/src/desk/components/DeskWindow.tsx:570-576`). That may be deliberate
  tolerance for dynamic window ids; this source audit found no observed impact
  and assigns no action or Tenet finding.
