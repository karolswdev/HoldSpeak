## 2. FINDINGs (ranked by what they cost the owner or the build)

- **F1 — Nothing sends a published project update.** (Corrected in round two, Codex Astra r1 finding 7: meeting results already go to Slack, C4.) The update is copy and confirm by his Phase 9 Q0 ruling; the table's own comment says "the product sends nothing" (`holdspeak/db/schema.py:4170-4176`).
- **F2 — The write seam already exists; the connector SDK is the read side.** `holdspeak/connector_sdk.py` describes read packs: `cli_enrichment` is "read-only CLI calls" (`:32`), `Snapshot` "never emit[s] effects" (`:767-776`), and the `acli_jira` / `acli_confluence` allow-lists are read-only verbs (`holdspeak/connector_packs/acli_jira.py:25-45`, `acli_confluence.py:27-46`). The write side is Phase 38's `holdspeak/plugins/gated_connector.py`: a `WriteConnectorManifest` with one permission and an allow-list that "can only narrow" (`:127-176`), and `build_gated_connector` = plan → kernel → interpret (`:236-288`). It has six live users (`github_issue_actuator.py`, `github_pr_actuator.py`, `webhook_post_actuator.py`, `slack_export.py`, `voice_macro_connector.py`, `missioncontrol_bridge.py`). **A channel is one `WriteConnectorManifest` + one `plan` + one `interpret`. No new SDK capability and no new plugin framework is needed.**
- **F3 — A CLI send is admitted as `subprocess.exec`, not `external.egress`.** `gh`, `acli` and `osascript` run through `run_subprocess_operation` (`holdspeak/kernel/subprocess_exec.py:227-292`); its admission hashes binary, argv and cwd only (`:155-164`; the argv prefix check at `:150-154`), not `input=`. A body passed on stdin (`--body-file -`) is outside that hash: the body must ride in argv, or the parent op's payload hash must cover the rendered document. An AGENT principal is refused (`:177-186`, `:265-266`) — the owner's "You, every time" is already the kernel's rule for CLI effects.
- **F4 — `nudge.send` records "result unknown" as "failed" and offers Send again.** A `gh` timeout is receipted `indeterminate` by the kernel (`subprocess_exec.py:282-289`), then `send_nudge` catches every exception as `outcome: failed` and returns the step to `proposed` (`project_steward_service.py:2049-2066`); the operation then ends on the named refusal `send_failed` (`holdspeak/services/steward_contract.py:649-660`). The kernel says unknown, the nudge says failed, and a second press can post the comment twice. Code-read; not run (no account on an isolated HOME).
- **F5 — The nudge's `gh` op has no parent.** `run_subprocess_operation` sends no `parent_operation_id` (`subprocess_exec.py:249-260`) and `_route` passes none (`gated_connector.py:201-216`), so the comment is a root `subprocess.exec` beside `nudge.send`, not its child (Article XI.1, "nesting inside an admitted operation exempts nothing"; XI.2 on children).
- **F6 — The four named direct `external.egress` callers allow only their own destination.** (Corrected in round two, Codex Astra r1 finding 7: not every caller.) Each of these passes `allowed_destinations=(destination,)` (`holdspeak/cadence_telegram.py:54`, `holdspeak/intel_queue.py:936`, `holdspeak/intel/engine.py:363`, `holdspeak/kernel/inference_runner.py:818`), so the check at `holdspeak/kernel/external_egress.py:168-169` cannot refuse them. `PermissionGate.open_outbound_socket` passes a manifest host list (`holdspeak/connector_runtime.py:194-233`), and the webhook actuator already has a configured host allow-list (`holdspeak/plugins/builtin/webhook_post_actuator.py:158-168`). Saved destinations add a per-target list for Send, frozen with the payload (`pm/roadmap/holdspeak-philo/phase-10-the-channels/design/send-lifecycle.md` section 5).
- **F7 — The file-write connector overwrites without a word.** `build_outbox_connector` writes `Path.write_text` to `outbox/<name>` (`holdspeak/plugins/builtin/followup_ticket_actuator.py:112-146`). Probe (`file-outbox-probe.out.txt`): two writes to `update.md` → one file, the second body; `../../escape.md` is clamped to `escape.md` (`:138`). Proof is path + bytes, no digest.
- **F8 — `acli` 1.3.36 cannot create or update a Confluence page.** `acli confluence page` offers only `view`; `blog create` exists (`--space-id`, `--title`, `--body` in storage-format XHTML, `--status current|draft`, `--json`). Jira has `workitem comment create` (`--key`, `--body` plain text or ADF, `--body-file`, `--jql`, `--json`) (`cli-probe.out.txt`). 1.3.39 is available; what it adds is unknown.
- **F9 — An `acli` send must switch the account first, under the existing lock.** `acli` has one active account per product; the providers switch and verify under one cross-process lock (`holdspeak/services/jira_provider.py:81-175`, `:535-590`; `holdspeak/services/confluence_provider.py:8`, `:270-300`, `:544-580`). A send is switch → status → create inside that lock.
- **F10 — Mail.app's `send` answers only true or false.** The scripting dictionary: `send` → "true if sending was successful" (`cli-probe.out.txt`, Mail sdef line 258-260); a `message id` is readable only on a stored message (line 592), not returned by `send`.
- **F11 — HTML rendering is available only by accident.** `markdown-it-py` imports in the venv but is not declared in `pyproject.toml` (a transitive dependency); the Phase 9 F14 lesson (`jsonschema`) says declare it if a channel uses it.
- **F12 — "Delivery" is a taken word in the code and the docs.** `holdspeak/delivery/` is the Delivery Runtime (HS-94-02, dw/gh delivery sources, `holdspeak/delivery/__init__.py:1-20`), and the repo runs Delivery Workbench. The product verb is **Send**; the code word is **channel**.
- **F13 — Slack already sends meeting results** (C4). The owner's pick leaves Slack Out; its path stays as it is.
- **F14 — "What is sent is what was previewed" exists as law for actuators.** `holdspeak/actuator_authority.py:1-40` binds payload hash, normalized destination, preview, renderer version and policy version at approval; the executor refuses a mismatch before egress (`holdspeak/plugins/actuator_executor.py:1-30`). A Send copies that parity, not the proposal table.
- **F15 — (round two) What each CLI reads a body from, and where the logins live** (`transport-probe.out.txt`). `gh issue comment` / `gh pr comment`: `--body-file <file>`, or `-` for stdin. `acli jira workitem comment create --body-file -` answered "failed to read comment body from file": no stdin; a 0600 file got past the read and stopped at the login. `acli confluence blog create`: `--from-file <file>`. `osascript` ran a fixed script that read a 0600 file holding `"quoted" & end tell -- not code` and returned it as text. `ARG_MAX` is 1,048,576. The `acli` binary links `github.com/zalando/go-keyring` (`macOSXKeychain.Get/Set`): its login is very likely in the macOS keychain, and `gh` keeps its token there too (`holdspeak/services/github_provider.py:81`). A scratch HOME therefore does not isolate them, and it never isolates Mail. Also (Codex Astra r1 finding 3): the subprocess receipt exposes the full argv (`holdspeak/kernel/subprocess_exec.py:199-213`) and a body in argv is visible in `ps`; the design puts the body in a private file.
- **F16 — (round three) The Confluence title and the GitHub identity.** `acli confluence blog create --generate-json`, `--from-json <0600 file>` and `--from-json … --title …` all answered `unauthorized: use 'acli confluence auth login'` on an isolated HOME (`confluence-json-probe.out.txt`): the login is checked before the file is read, so whether `--from-json` carries the title is **unknown** until the real-account leg. The design keeps the title inside the frozen payload and names a limit for the fallback (`pm/roadmap/holdspeak-philo/phase-10-the-channels/design/send-lifecycle.md` section 3). The GitHub connection row is one fixed id (`wpc_github`, `holdspeak/services/github_provider.py:220`) whose account every probe rewrites (`:305-311`; Codex Astra r2 changed it from one login to another through the real provider). It cannot identify who will post: the destination freezes `{host, login}` and the send checks the effective login before dispatch (design section 5).
- **F17 — (round four) Key custody for an email provider, on every platform.** `keyring` 25.7.0 is a core dependency (`pyproject.toml:60`). Its macOS, Secret Service and Windows backend modules all import here; on this Mac the active backend is `keyring.backends.macOS.Keyring`, **even under an isolated HOME** (`keyring-probe.out.txt`), so a lane must inject a memory store and never touch the real keychain. The People key store admits only macOS and Secret Service (`holdspeak/people/keys.py:53-71`); the email store adds Windows by name and refuses every other backend (`fail`, file-based) by name. SendGrid itself was not called: no key exists in a lane.

**Real sends need his accounts.** On an isolated HOME: `gh` "not logged into any GitHub hosts"; `acli` "unauthorized" for Jira and Confluence (`cli-probe.out.txt`). A scratch HOME isolates neither the keychain logins (F15) nor Mail. The real sends are therefore a separate leg on his own session, only to targets he authorizes (the charter's Q6), apart from the isolated rehearsals.

## 4. Email: the transports, for the owner's word

**Round four — the owner ruled (2026-09-28):** "Nah man. Not mail.app since it wouldn’t work on non-Macs. Let’s have it declare an interface that would allow us to plug it into major providers like sendgrid and so on." The table and the recommendation below are the record of rounds one to three; they are superseded. Email is a declared provider interface with SendGrid first (`pm/roadmap/holdspeak-philo/phase-10-the-channels/design/send-lifecycle.md` section 8). Mail.app is parked (BACKLOG "Mail.app draft channel").

**Recommendation: (b) Mail.app, on three conditions** (round two, Codex Astra r1 finding 6): his work account is already in Mail, his company allows that use, and Automation works from the hub's real launch context. Story 03 checks all three on his desk before any build. HoldSpeak holds no secret, and Mail sends from an account he set up. The outcome label is **HANDED TO MAIL**: HoldSpeak does not see the server, it does not promise the Sent box or the recipient, and Mail may hold the message in its Outbox and try again by itself (that is Mail finishing the first handoff; HoldSpeak never submits again). What `false` leaves in the Outbox is probed offline before `false` is mapped. If a condition fails: (a), where the provider allows app passwords, with SMTP stopping before DATA unless every recipient is accepted; else email waits. (c) fails Tenet 1. (d) is the manual channel with a head start.
