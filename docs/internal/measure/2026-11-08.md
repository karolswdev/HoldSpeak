What each fix was:

1. The desk is drawn at once (`web/src/routes.tsx`, `web/src/main.tsx`, `web/src/runtime/preloadable.ts`). React 19 reveals a Suspense boundary no sooner than 300 ms after its fallback showed. The lazy Desk route suspended on every open: a trace showed the main thread idle from 33 ms to 331 ms, waiting on that timer, with the desk chunk in since 39 ms. The chunk is now read before the first render. The earlier first paint was the loading face; the first paint is now the desk.
2. Meeting names without a new Intl formatter per call (`web/src/desk/surface/format.ts`, `windowName.ts`): 99 ms of main thread per open in a CPU profile.
3. Roadmaps: an old answer is served while `dw` reads again in the background; a cold read reads the projects side by side (`holdspeak/web/routes/roadmaps.py`). The desk's loader waits for this read; each 5 minutes it ran `dw check` and `dw next` for every project (about 2 s). A changed file is still read before the answer.
4. Projections: the receipt events are two index searches, not an OR that walked the timestamp index over the whole log (`holdspeak/db/projections.py`). No migration: the indexes existed.
5. Observer: a result summary reads the head of a large result (`holdspeak/services/observer.py`). Each observed call redacted and encoded its whole result to keep 2048 characters: 70 % of a Needs-you build.

Not met: desk open under 15 requests (51). The desk loader reads 19 collections, and the windows read about 30 more. Fewer requests needs one batched read transport; 75 web test files stub `fetch` per path and about 30 browser files route or watch requests per path, so it is its own lane. The needs-you and Room reads were under 150 ms before this lane on this seed; they are now 39 ms and 8 ms.
