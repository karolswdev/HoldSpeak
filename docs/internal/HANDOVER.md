## Part 0: the grand refactor, in one paragraph

The owner, 2026-11-08 evening: "my vision was for the entire system to be service-based… literally every single thing it can do, it is via a call to an API, an interface… the truest form of ports and adapters… a big success of this app being refactored is when we funnel all the actions through all of the common interfaces… then we can enrich our MCP layer… it has to be a lot better… eventually also HTTP APIs or winding up CLIs around this… our desk environment is just a client of all of this at the end of the day." And: "sequences and workflows… I think of it as programs… that should be the angle." The backbone is services. One declared operation per capability produces the HTTP route, the MCP tool and the CLI command. Programs are the one engine for work that runs. The engine door is the one way to call a model. The Desk is one client. Every change removes a seam or a second implementation and never adds one; the measure is operations funnelled, routes and tools that are twins, lines parked, never merges counted.
