The Note as a workspace

Three directions for the Note window, drawn at real size (760 × 560) over the real 1440 desk, in our tokens and window grammar. Each one answers the same six questions. The recommendation is first.

The worked example is an architect's note, "Ledger cutover plan": a heading, a paragraph with a PR link, a task list, a flowchart, a decision line and an @Priya mention. The live preview (headings, lists, task boxes, links, code, tables) is assumed, as the parallel lane builds it.

Today: the title shows three times (menu bar, title bar, title row). The question band and the task rows push the editor down. Links collect in a "Linked items" fold under the text. The Project link is a well that opens under the editor.

What a note can do today

Read from the code on main 94129956f. One line each.

Verbs (toolbar)

  • Done: saves, then closes the window. ThoughtWorkspaceWindow.tsx:592
  • Ask about this: saves, opens the Ask window with the note in About and the selected text quoted. :593, :499
  • Find the tasks: the hub reads the note and returns task and decision rows. :594, POST /api/notes/{id}/outcomes/find
  • Project ▾: opens a well to pick a project and Add (a project resource, "related"). ProjectWell.tsx:27
  • Send…: saves, then the Send wells replace the editor (destinations, preview, Send). :596, :659
  • Mic: speaks into the note at the caret; a kept voice draft offers Insert at caret or Copy. ThoughtDocumentPane.tsx:135, :48
  • ⌘S saves; ⌘↵ adds the answer, adds the draft, or is Done. :540–556

Wells and bands

  • The question band: a refinement turn asks a question; answer by text or voice, then Add to note. :600–611
  • The draft band: a refinement draft; Add to note appends it (never replaces your words). :614, :374
  • Task rows: "Who owes what" and "Decisions" ledgers; Confirm, Edit, Dismiss per row. NoteOutcomesWell.tsx:121–193
  • Project well: a project picker with Add and Close. ProjectWell.tsx:41
  • Linked items: a fold under the text with one Button per object link in the body. ReadingDocument.tsx:80
  • Diagram: a mermaid block draws as a flowchart in place. mermaidPreview.ts
  • Built, not mounted: TaskWell (Task, Who, When) and ThoughtReadsWell ("Add notes" context). No import outside their own files.

Returns

  • From Ask: Add to note grows the note; a clean window reads it again, a dirty one shows Changed elsewhere with Reload. :262
  • Back from Ask: the caret goes back to the quoted range, or the line says Source changed. askReturn.ts:6
  • A draft added: the added range is checked by SHA-256 and revealed. :75
  • Status bar: the save lamp and words (Saved just now, Changed elsewhere) and one verb: Reload, Retry or Stop. :640
  • Return to Project: a title-bar verb when the note opened from a Project. :737

Filing and relations

  • Project: PUT /api/projects/{p}/resources/note:{id}. The note does not show which projects hold it.
  • Drawers: a note icon on the floor drops into a zone drawer (zone_file MCP).
  • People: a person's notes are a People write (people_note_create), not a link from this note.
  • Object menu: Open, Rename, Duplicate, Delete, Hand to agent. objectMenu.ts:60
  • Object links: a Markdown link with a ref (people:, project:, decision:, coder:…) opens that object's window. openObject.ts:172
  • Not known to the note today: the meeting it came from (the source is typed, voice or note, thoughts.ts:15), its projects (no reverse read), plain PR numbers and Jira keys.

A on the phone (393)

The margin becomes a sheet that rises from the status bar. The name is in the title strip only. Rows are 44 px.

What each direction costs

A. Page and margin. Changes: ThoughtWorkspaceWindow.tsx (the bands and the outcome well move into the margin; the editor stays put), ThoughtDocumentPane.tsx (the title row goes; the empty-note starts; Linked items fold retired), NoteOutcomesWell.tsx (the rows render as margin rows), components/DeskWindow (rename in the title bar), DeskMenuBar.tsx (no title in the middle), thought-workspace.css. New kit species: Margin (a wing inside a window's content, which collapses to a sheet on the phone), ObjectToken (a CodeMirror decoration for people:, project:, decision:, PR and Jira refs), PeekCard (a hover card with one or two verbs), and a pressable StatusBar item. Hub: a reverse read "which projects hold this note" and a source-meeting field for "From…" (neither exists, see the inventory); rows carry no source offsets, so the row-to-line tie is a client text match that falls back to stacking.

B. Drawer and Info wing. Changes: the same window file, plus a new title rule: the title becomes the body's first heading, so thoughtTitle.ts, ownTitle and the window name follow the first line, and the hub's title field must track it (a rename becomes an edit of the text). New species: Drawer (a resizable bottom pane with segmented tabs), InfoWing (sections of 30 px object rows with a small card). The list view reuses ObjectList dense. The same two hub reads as A. Risk: a page H1 is what the window grammar removed elsewhere.

C. Inline. Changes: the editor itself. Answer plates are CodeMirror block widgets inside the document, which must survive edits, the reveal code (verifiedReveal) and the Ask return range. Gutter marks need each found row's exact text range, and the hub does not return one today (noteOutcomes.ts:9), so note_find_tasks must change. New species: a gutter extension, a block widget, a slash menu, a hover card. Highest cost and the most risk to the sole-writer save path.

Order of build for A

Smallest useful slice first. Each one is one lane and can merge alone.

  1. The title once. Remove the menu-bar title and the title row; rename in place in the title bar. Small, and the owner sees it at once.
  2. The margin, with Find the tasks. The new Margin species; the outcome rows move into it and arrive one by one; the editor no longer moves down.
  3. Row to line. Hover a margin row and its line lights; press it and the caret goes there (client text match).
  4. Answers in the margin. The question and draft bands, and Ask's return, become margin notes beside the quoted passage, with Add to note and Dismiss.
  5. Objects in the text. ObjectToken for the refs that open today (people, project, decision), then PR numbers and Jira keys; press opens the window; the Linked items fold is retired.
  6. The status bar place line. Needs the hub's reverse read of a note's projects; then the source meeting when the hub records it.
  7. The empty note. The cue line and the four starts.
  8. Peek cards on hover.
  9. Motion. The save lamp's one breath, the task tick, the row arrival.
  10. The phone. The margin as a sheet from the status bar.
