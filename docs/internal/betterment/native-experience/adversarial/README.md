## Reading the verdicts

A verdict assesses whether the original family audit is sufficient to guide
implementation. It is not a production incident severity, a merge gate, or
owner acceptance. P0/P1 and High/Medium within individual records prioritize
the reviewer’s audit corrections; the reconciliation will rank delivery work
by demonstrated owner cost and shared benefit. Existing guards and useful
behavior must survive that work. Do not implement every proposed abstraction
or turn all acceptance challenges into new screens.

## Reviewer brief

Read TWO-BRAINS first and the current CLAUDE fast cycle, Constitution Seven
Tenets, UX-CANON, APPLICATION-MODEL.md and the assigned inventory record.
Treat the inventory as a hypothesis to challenge. Inspect real relevant
production paths and representative test assertions; test existence is not
execution. Follow the job from trigger and input through result, recovery and
return to work. Confirm active versus parked code, backend versus UI contracts,
and coarse capability associations versus real workflow behavior. Anchors are
baseline-specific and may drift.

Look for missing actors, variants, fast/repeat use, alternatives, transitions,
interruption, stale state, conflicts, offline/provider/permission limits,
multiple windows and persistence where the job actually needs them. Do not
impose explorer features on every simple job or turn each edge case into a new
screen. Challenge whether the workflow family itself should be split, merged,
renamed or bounded, preserving the existing id as traceability.

For convergence, name other actual inventory ids and the exact reusable state,
behavior or visual composition. Identify first consumers and what must stay
separate; include a counterargument to unnecessary consolidation. Prefer the
existing public controls, command registry, compositor, draft/voice/receipt
machinery and actual product patterns. No generic wizard, new runtime,
parallel registry, approval framework or all-at-once rewrite.

For user value, assess the senior architect's Tuesday job: speed, familiarity,
clarity, discovery, control, recovery, cognitive effort and craft. Where a real
capture is available, inspect it and name the state/viewport; distinguish that
observation from source-based design inference. Source alone cannot certify
beauty, accessibility, performance or owner delight. Do not rubber-stamp or
manufacture a defect to fill a quota.

## Required individual record

Write only the assigned `adversarial/<workflow_id>.md`, 450–800 useful words
(extend only when the case needs it). No other file edits, stage/commit,
builds/tests, live Desk calls, provider/native actions or owner-state writes.
Worker holds for SHIP. Other workers own their named record; root owns the
index, synthesis, source snapshot and existing docs/status.

Start with workflow id, job, baseline, reviewer task name, and evidence class.
Then use these literal labels and sections:

- `VERDICT: RATIFY | RATIFY-WITH-CONDITIONS | DO-NOT-RATIFY` — completeness of
  this audit as an implementation brief, not readiness of the product.
- `## Totality` — actual end-to-end job and missing/over-broad use-case scope.
- `FINDINGS:` — numbered, prioritized, each with path:line evidence, owner cost,
  the Tenet it fails, and the concrete correction. Say none if none material.
- `## Convergence` — named related workflow ids, shared contract/first consumers,
  retained boundaries and a counterargument to merging.
- `## User experience` — explicit source/capture-based judgment of whether the
  flow is likely to please; concrete improvements and honest unknowns.
- `CONDITIONS:` — what changes make the audit sufficient; no new owner gate.
- `MISSED:` — the most important omitted scenarios, ranked by owner cost.
- `TUESDAY:` — one clear user-job assessment.
- `## Acceptance challenges` — 3–5 falsifiable real-job scenarios, including
  relevant recovery/return paths; no fake unsupported actions.
- `UNKNOWN:` — precisely what was not observed or proved, including no test
  execution, no owner acceptance and no new performance claim.

Final worker reply: id, verdict, top two material findings, convergence targets,
output path. Keep source citations concrete; no glob or invented test paths.
